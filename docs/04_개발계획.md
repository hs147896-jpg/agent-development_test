# 카페 판매·재고·손익 관리 프로그램 개발 계획

## 1. 문서 목적

이 문서는 `01_PRD.md`, `02_FRD.md`, `03_TRD.md`와 `design` 폴더의 시안을 바탕으로 1차 개발 범위를 실제 구현 순서에 맞게 나눈 계획이다.

각 작업 묶음(EPIC)은 사용자가 화면에서 확인할 수 있는 완성 결과를 만든다. 계산 정확성, 데이터 저장, 입력 검증, 기본 오류 처리는 별도 작업으로 미루지 않고 관련된 모든 User Story의 완료 조건에 포함한다. 화면만 표시하거나 가짜 데이터로 동작하는 상태는 완료로 인정하지 않는다.

## 2. 전체 작업 순서

총 **3개 EPIC, 13개 User Story**로 구성한다.

| 순서 | EPIC | Story 수 | 이 순서로 개발하는 이유 |
|---|---|---:|---|
| 1 | 기준 데이터와 운영 현황 조회 | 5개 | 모든 입력과 계산의 기준이 되는 저장 구조와 계산 결과를 먼저 검증해야 한다. |
| 2 | 운영 기록 입력·수정 | 5개 | 판매·비용·재고 기록을 바꿨을 때 EPIC 1의 결과가 정확히 갱신되는지 확인한다. |
| 3 | 파일 관리와 배포 | 3개 | 검증된 저장·계산 방식을 엑셀과 백업에도 동일하게 적용한 뒤 실제 사용 환경에 배포한다. |

## EPIC 1. 기준 데이터와 운영 현황 조회

**상태: `[완료]` — 2026-10-12 구현·자동 검사·사용자 확인 통과**

초기 자료를 안전하게 저장하고, 손익·메뉴 수익성·재고 현황을 실제 데이터로 확인하는 단계이다.

### Story 1.1 초기 자료 불러오기와 저장

- **사용자가 할 수 있는 일:** 처음 프로그램을 열어 제공된 매장 자료를 확인하고, 이후 같은 기기에서 다시 사용할 수 있다.
- **자동 검사:** 자료의 필수 항목, 날짜, 금액, 식별번호와 서로 연결되는 메뉴·재료 정보를 검사한다. 문제가 있으면 일부만 저장하지 않고 원인을 안내한다.
- **화면에서 확인할 행동:** 프로그램을 처음 연 뒤 새로고침한다.
- **예상 결과:** 같은 기준일과 기록 건수가 유지되며, 초기 자료가 중복으로 추가되지 않는다.

### Story 1.2 영업일 마감 관리

- **사용자가 할 수 있는 일:** 날짜별로 기록 입력이 끝났음을 표시하거나 마감을 취소할 수 있다.
- **자동 검사:** 존재하지 않는 날짜나 처리할 수 없는 미래 날짜를 막고, 마감 상태 변경이 손익 계산에 정확히 반영되는지 검사한다.
- **화면에서 확인할 행동:** 특정 날짜를 마감한 뒤 손익 화면을 보고, 다시 마감을 취소한다.
- **예상 결과:** 마감하면 해당 날짜 실적이 실제 손익에 포함되고, 취소하면 제외된다.

### Story 1.3 기간별 실제 손익 확인

- **사용자가 할 수 있는 일:** 일·주·월·분기·반기·연간 실적을 선택하고, 매출 경로별 금액과 계획 금액을 함께 확인할 수 있다.
- **자동 검사:** 마감된 날짜만 실제 실적에 포함하고, 매출·할인·수수료·재료비·운영비를 중복 없이 집계한다. 자료가 부족하면 숫자를 추측하지 않고 안내한다.
- **화면에서 확인할 행동:** 같은 기준일에서 월간과 연간을 차례로 선택한다.
- **예상 결과:** 선택한 기간에 맞게 매출·비용·이익과 매출 경로별 값이 바뀌며, 일부 기간만 마감된 경우 그 상태가 표시된다.

### Story 1.4 메뉴별 수익성 확인

- **사용자가 할 수 있는 일:** 메뉴별 판매금액, 직접 들어간 비용, 이익을 비교하고 메뉴 하나의 상세 내용을 확인할 수 있다.
- **자동 검사:** 판매 당시 가격·할인·수수료·원가 기록을 사용해 결과를 계산한다. 판매량이 0이거나 가격·재료 정보가 부족한 경우를 별도로 처리한다.
- **화면에서 확인할 행동:** 기간을 선택한 뒤 메뉴를 이익순으로 정렬하고 메뉴 하나를 선택한다.
- **예상 결과:** 메뉴별 판매량과 수익성이 순서에 맞게 표시되고, 선택한 메뉴의 비용 구성과 주의사항을 확인할 수 있다.

### Story 1.5 재료 잔량 확인

- **사용자가 할 수 있는 일:** 재료별 시작 재고, 입고, 판매 사용량, 폐기, 실제 재고조사 결과와 현재 잔량을 확인할 수 있다.
- **자동 검사:** 같은 기록을 두 번 반영하지 않고 단위를 확인한다. 잔량이 0이거나 음수인 재료는 정상 재료와 구분한다.
- **화면에서 확인할 행동:** 재고 화면에서 특정 재료의 변동 내역과 상태를 확인한다.
- **예상 결과:** 각 증감 내역을 더하고 뺀 결과가 현재 잔량과 일치하며, 부족한 재료가 눈에 띄게 표시된다.

### EPIC 1 완료 기준

- 네 개의 주요 시안 화면에 실제 초기 자료가 표시된다.
- 손익·메뉴 수익성·재고 결과가 원본 기록과 일치한다.
- 새로고침하거나 프로그램을 다시 열어도 자료가 유지된다.
- 자료가 부족하거나 잘못된 경우 숫자를 임의로 만들지 않고 안내한다.

## EPIC 2. 운영 기록 입력·수정

**상태: `[완료]` — 2026-10-12 구현·자동 검사·사용자 확인 통과**

판매부터 손익과 재고까지 연결되는 핵심 사용 흐름을 완성하는 단계이다.

### Story 2.1 운영 기록 찾기

- **사용자가 할 수 있는 일:** 판매·비용·입고·폐기·재고조사 기록을 종류별로 나누어 보고 검색할 수 있다.
- **자동 검사:** 검색 결과 수와 목록 수가 일치하는지, 페이지를 이동해도 기록이 누락되거나 중복되지 않는지 검사한다.
- **화면에서 확인할 행동:** 기록 종류를 바꾸고 날짜나 검색어로 기존 기록을 찾는다.
- **예상 결과:** 조건에 맞는 기록만 표시되며, 결과가 없으면 빈 목록 대신 안내 문구가 나온다.

### Story 2.2 판매 기록 관리

- **사용자가 할 수 있는 일:** 판매 기록을 추가·수정·삭제할 수 있다.
- **자동 검사:** 날짜, 메뉴, 수량, 가격, 할인, 수수료와 중복 기록을 검사한다. 처리 중 오류가 나면 변경 전 상태로 되돌린다.
- **화면에서 확인할 행동:** 판매 한 건을 추가하고 메뉴 수익성·손익·재고 화면을 확인한 뒤 수정하거나 삭제한다.
- **예상 결과:** 판매금액과 메뉴 이익이 바뀌고 사용 재료가 차감된다. 수정·삭제할 때는 기존 영향이 한 번만 제거된 뒤 새 결과가 반영된다.

### Story 2.3 비용 기록 관리

- **사용자가 할 수 있는 일:** 임대료·인건비·공과금 등 비용 기록을 추가·수정·삭제할 수 있다.
- **자동 검사:** 날짜, 비용 종류와 0보다 큰 금액을 검사하고, 저장 실패 시 일부 변경만 남지 않도록 한다.
- **화면에서 확인할 행동:** 비용 한 건을 추가한 뒤 손익 화면과 메뉴 수익성 화면을 확인한다.
- **예상 결과:** 전체 손익은 비용만큼 변하지만 메뉴별 직접 수익성은 변하지 않는다.

### Story 2.4 입고·폐기 기록 관리

- **사용자가 할 수 있는 일:** 재료 입고와 폐기 기록을 추가·수정·삭제할 수 있다.
- **자동 검사:** 재료, 날짜, 수량, 단위를 확인한다. 폐기는 화면에서 양수로 입력받되 재고에서는 감소로 처리한다.
- **화면에서 확인할 행동:** 같은 재료에 입고와 폐기를 각각 입력한 뒤 잔량을 확인한다.
- **예상 결과:** 입고 수량만큼 늘고 폐기 수량만큼 줄며, 수정·삭제 결과도 즉시 반영된다.

### Story 2.5 실제 재고 기록

- **사용자가 할 수 있는 일:** 특정 날짜에 직접 확인한 실제 재고 수량과 차이가 난 이유를 기록할 수 있다.
- **자동 검사:** 같은 날짜·재료의 중복 재고조사와 음수 수량을 막는다. 재고조사 결과가 여러 번 조정값으로 더해지지 않는지 검사한다.
- **화면에서 확인할 행동:** 계산상 잔량과 다른 실제 수량을 입력하고 이후 입고 또는 판매 기록을 추가한다.
- **예상 결과:** 실제 수량이 새로운 기준이 되고, 이후 변동분만 더하거나 빼서 잔량이 표시된다.

### EPIC 2 완료 기준

- 모든 운영 기록을 실제로 추가·수정·삭제할 수 있다.
- 변경 내용이 저장되고 새로고침 후에도 유지된다.
- 한 기록의 영향이 손익·메뉴 수익성·재고에 정확히 한 번씩 반영된다.
- 필수값 누락, 잘못된 숫자, 중복 기록 및 저장 실패가 안전하게 처리된다.

## EPIC 3. 파일 관리와 배포

**상태: `[진행 중]` — 2026-10-12 코드 구현·자동 검사·개발자 브라우저 검사 통과, 사용자 확인과 Vercel 실제 배포 대기**

여러 기록을 한 번에 가져오고, 자료를 복구하며, 실제 주소에서 사용할 수 있게 하는 단계이다.

### Story 3.1 판매 엑셀 가져오기

- **사용자가 할 수 있는 일:** 정해진 엑셀 양식을 내려받아 판매 기록을 작성하고 프로그램으로 가져올 수 있다.
- **자동 검사:** 파일 형식, 열 이름, 날짜, 숫자, 메뉴, 중복 식별번호와 기존 기록 중복을 검사한다. 오류 행이 있으면 전체 가져오기를 중단한다.
- **화면에서 확인할 행동:** 정상 파일과 오류가 있는 파일을 차례로 가져온다.
- **예상 결과:** 정상 파일은 모든 기록이 한 번에 저장되고 관련 계산이 갱신된다. 오류 파일은 저장되지 않고 수정할 위치와 이유가 표시된다.

### Story 3.2 전체 자료 백업·복원

- **사용자가 할 수 있는 일:** 전체 자료를 JSON 파일로 내려받고, 백업 파일을 선택해 이전 상태로 복원할 수 있다.
- **자동 검사:** 백업 파일의 종류·버전·필수 자료·연결 관계를 검사한다. 손상된 파일은 기존 자료를 바꾸지 않고 거부한다.
- **화면에서 확인할 행동:** 백업 후 기록을 변경하고, 방금 만든 파일로 복원한다.
- **예상 결과:** 복원 전 확인 안내가 나오며, 승인하면 기록과 계산 결과가 백업 시점과 같아진다.

### Story 3.3 배포된 프로그램 사용

- **사용자가 할 수 있는 일:** Vercel 주소에서 프로그램을 열고 핵심 업무를 수행할 수 있다.
- **자동 검사:** 코드 검사, 계산 검사, 주요 사용 흐름 검사와 배포용 프로그램 생성을 자동 실행한다. 운영 기록이 외부 서버로 전송되지 않는지도 확인한다.
- **화면에서 확인할 행동:** 배포 주소에서 판매 기록을 추가하고 손익·메뉴 수익성·재고를 확인한 뒤 새로고침한다.
- **예상 결과:** 각 결과가 즉시 갱신되고 새로고침 후에도 유지된다. 심각한 오류 없이 GitHub의 확정된 코드와 같은 버전이 실행된다.

### EPIC 3 완료 기준

- 정상 엑셀은 가져오고 잘못된 파일은 자료 변경 없이 거부한다.
- 백업한 전체 자료를 동일하게 복원할 수 있다.
- 자동 검사에 통과한 코드가 GitHub에 보관되고 Vercel에 배포된다.
- 운영 자료는 사용자의 브라우저에 저장되고 외부로 임의 전송되지 않는다.

## 3. 1차 개발 완료 판단

다음 조건을 모두 만족하면 1차 개발을 완료한 것으로 판단한다.

1. 판매 기록을 입력하면 메뉴별 수익성, 실제 손익, 재료 잔량이 서로 연결되어 갱신된다.
2. 판매·비용·입고·폐기·재고조사 기록을 저장하고 다시 열어도 유지된다.
3. 모든 계산 결과가 PRD·FRD에서 정한 기준 및 TRD의 구현 원칙과 일치한다.
4. 잘못된 입력이나 파일 때문에 기존 자료 일부만 변경되는 일이 없다.
5. 엑셀 가져오기와 JSON 백업·복원을 실제 파일로 확인할 수 있다.
6. 자동 검사를 통과한 프로그램을 Vercel 배포 주소에서 사용할 수 있다.
