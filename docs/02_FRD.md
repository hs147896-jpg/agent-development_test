- 문서 상태: 1차 기능 요구사항 확정
- 작성일: 2026-10-12
- 기준 문서: `docs/01_PRD.md`
- 참고 시안: `design/_1`~`design/_4`, `design/apex_operations/DESIGN.md`
- 대상 범위: 4시간 이내 1차 구현(MVP)

## 1. 문서 목적과 읽는 법

이 문서는 사용자가 무엇을 입력하거나 선택하면 프로그램이 무엇을 처리하고, 화면과 파일에 어떤 결과를 내는지 정의한다. 개발 용어 대신 매장 운영 흐름을 기준으로 설명한다.

요구사항의 상태는 다음과 같이 구분한다.

| 표시 | 의미 |
|---|---|
| `[확정]` | PRD에서 정해졌거나 PRD와 시안이 일치하는 내용 |
| `[시안 반영]` | PRD 범위 안에서 시안이 구체화한 내용 |
| `[결정]` | PRD 이후 기능 설계에서 추천안으로 확정한 내용 |
| `[2차]` | 1차 구현 이후 확장할 내용 |

## 2. 1차 프로그램의 기능 구성

| 영역 | 사용 목적 | 주요 결과 |
|---|---|---|
| 실적·손익 | 선택 기간의 마감 실적과 매장 전체 손익 확인 | 순매출, 직접원가, 운영비, 영업이익, 채널별 실적 |
| 메뉴 수익성 | 메뉴별 판매 성과와 직접비용 기준 수익성 비교 | 판매수량, 순매출, 직접원가, 공헌이익, 마진율 |
| 재료·재고 | 판매·입고·폐기·실사를 반영한 재료 잔량 확인 | 현재 예상 잔량, 실측수량, 정상·소진·음수 상태 |
| 기록·가져오기 | 판매·비용·재고 기록 관리와 판매 엑셀 가져오기 | 저장된 기록, 가져오기 결과, 오류·중복 내역 |
| 백업·복원 | 한 기기의 전체 자료 보관과 이전 상태 복원 | 전체 백업 파일, 복원 결과 |

상단 이동 메뉴는 시안과 같이 `실적·손익`, `메뉴 수익성`, `재료·재고`, `기록·가져오기`로 구성한다. `백업·복원`은 공통 기능으로 제공한다.

## 3. 공통 기능 요구사항

### COM-00. 초기 자료 준비

**상태:** `[확정]`

- 프로그램의 최초 자료는 제공된 JSON 한 형식에서 준비한다.
- 공급사, 재료, 메뉴, 레시피, 재료 가격 이력, 영업 달력, 판매, 초기재고, 재고 기록, 월 비용 계획, 비용 기록, 자료 정보를 한 번만 반영한다.
- 제공된 전체 엑셀 원본을 별도로 다시 읽어 같은 자료를 중복 반영하지 않는다.
- 1차에서 공급사·재료·메뉴·레시피·가격 이력 등 기준정보는 조회에 사용하며 사용자가 편집하지 않는다.

오류·예외:

- JSON을 읽을 수 없거나 필수 자료 묶음이 빠졌으면 일부 자료만 정상인 것처럼 시작하지 않는다. 빠진 자료를 알리고 초기 준비 실패 상태를 표시한다.
- 같은 판매·비용·재고 ID 또는 연결할 수 없는 메뉴·재료·공급사 ID가 발견되면 해당 문제를 알리고 계산 결과를 확정하지 않는다.

### COM-01. 기준일과 마감 상태

**상태:** `[확정]`

사용자 동작:

- 사용자는 날짜별 기록을 마감 또는 미마감으로 관리한다.
- 사용자는 각 결과 화면에서 적용된 기준일과 마감 범위를 확인한다.

프로그램 처리:

- 실제 실적과 실제 손익에는 마감된 날짜만 포함한다.
- 선택 기간 안의 미마감 날짜는 매출 0원으로 바꾸지 않고 집계에서 제외한다.
- `[결정]` 마감은 그 날짜의 판매·비용 기록 입력을 완료했다는 뜻이다. 마감된 날짜에 판매 기록이 없으면 실제 무매출 0원으로 취급한다.

화면 결과:

- 최근 마감일과 마감 상태를 표시한다.
- 선택 기간에 미마감 날짜가 있으면 날짜 범위와 일수를 알린다.
- 일부 기간만 집계된 월·분기·반기·연간 결과에는 포함된 실제 날짜 범위를 함께 표시한다.

저장 결과:

- 날짜별 마감 상태를 영업 달력 기록에 저장한다.

오류·예외:

- 마감 상태를 읽을 수 없으면 해당 날짜는 실제 실적에 포함하지 않고 `마감 상태 확인 필요`로 표시한다.
- 시안의 `매일 오전 04:00 POS 동기화 기준 자동 확정`은 외부 POS 연동이 필요한 기능이므로 1차에 적용하지 않는다. 1차 마감은 사용자가 관리한다.

### COM-02. 기간 선택

**상태:** `[확정]`

사용자 동작:

- 사용자는 일간, 주간, 월간, 분기, 반기, 연간 중 하나를 선택하고 기준 날짜 또는 기간을 선택한다.

프로그램 처리:

- 일간은 선택한 하루를 대상으로 한다.
- 주간은 월요일부터 일요일까지로 본다.
- 월간은 매월 1일부터 말일까지로 본다.
- 분기는 1~3월, 4~6월, 7~9월, 10~12월로 본다.
- 반기는 1~6월과 7~12월로 본다.
- 연간은 1월 1일부터 12월 31일까지로 본다.
- 실제 결과는 위 기간 중 마감된 날짜만 합산한다.

화면 결과:

- 선택 단위, 전체 기간, 실제 포함 기간을 구분해 표시한다.
- 자료 시작일보다 앞이거나 마지막 마감일보다 뒤인 구간이 있으면 `일부 기간 자료` 안내를 표시한다.

오류·예외:

- 선택 기간에 마감된 날짜가 하나도 없으면 금액을 0으로 단정하지 않고 `마감된 자료 없음`으로 표시한다.
- 시작일이 종료일보다 늦은 잘못된 기간은 조회하지 않고 날짜를 다시 선택하도록 알린다.

### COM-03. 숫자·단위·빈칸 표시

**상태:** `[확정]`

- 금액은 원(KRW), 재료는 원본에 지정된 g·ml·개 단위로 표시한다.
- 빈칸, 실제 숫자 0, 계산할 수 없음, 해당 없음은 서로 구분한다.
- 금액·수량은 원본 정밀도를 보존한다. 화면에서는 읽기 쉽게 천 단위 구분을 사용할 수 있다.
- 서로 다른 재료 단위를 합쳐 하나의 재고 수량으로 표시하지 않는다.

### COM-04. 공통 저장과 결과 갱신

**상태:** `[확정]`

- 판매·비용·재고 기록을 추가·수정·삭제하면 관련 실적, 수익성, 손익, 재고 결과를 다시 계산한다.
- 저장된 기록과 마감 상태는 프로그램을 종료했다가 다시 사용해도 유지돼야 한다.
- 저장에 성공한 뒤에만 새 결과를 확정해 표시한다.
- 저장에 실패하면 기존 기록과 기존 계산 결과를 유지하고 실패 이유를 알린다.

## 4. 실적·손익 기능

### PNL-01. 기간별 실제 실적 요약

**상태:** `[확정]`

사용자 동작:

- 사용자는 기간 단위와 기준 기간을 선택한다.

프로그램 처리:

- 마감된 판매 기록을 메뉴·채널과 관계없이 합산한다.
- 할인은 순매출에 이미 반영되므로 손익에서 다시 차감하지 않는다.
- 판매 당시 저장한 식재료 원가, 포장 원가, 결제수수료를 사용한다.
- 현재 재료 가격으로 과거 판매 원가를 다시 계산하지 않는다.

화면 결과:

- 순매출, 할인금액, 식재료비, 포장비, 결제수수료, 직접원가, 운영비, 실제 영업이익을 표시한다.
- 시안의 일자별 표에는 날짜, 마감 상태, 판매수량, 순매출, 결제수수료, 식재료비, 포장비, 운영비, 영업이익, 비고를 표시한다.
- 원본 판매 자료는 주문 건수가 없으므로 시안의 `판매건/수량` 중 주문 건수는 표시하지 않는다. 판매수량만 표시한다.

계산 제안:

```text
판매총액 = 판매수량 × 판매당시단가
순매출 = 판매총액 - 할인금액
식재료비 = 판매수량 × 개당식재료원가
포장비 = 판매수량 × 개당포장원가
직접원가 = 식재료비 + 포장비 + 결제수수료
공헌이익 = 순매출 - 직접원가
실제 영업이익 = 공헌이익 - 운영비
영업이익률 = 실제 영업이익 ÷ 순매출 × 100
```

- 기존 자료의 순매출·결제수수료·판매 당시 원가 값은 과거 기록으로 보존한다.
- `[결정]` 새 판매 기록의 결제수수료는 사용자가 실제 금액을 직접 입력한다. 자료에 없는 수수료율로 자동 계산하지 않는다.

오류·예외:

- 순매출이 0이면 영업이익 금액은 표시할 수 있지만 영업이익률은 `계산 불가`로 표시한다.
- 필수 원가가 비어 있으면 해당 기록을 0원 원가로 보지 않는다. 관련 원가와 영업이익을 `계산 불가`로 표시하고 원인을 알린다.
- 할인금액이 판매총액보다 크면 저장 또는 가져오기를 막고 해당 값을 수정하도록 알린다.
- 음수 판매수량은 1차에서 지원하지 않으며 오류로 처리한다. 반품 처리는 PRD에 없는 기능이므로 추가하지 않는다.

### PNL-02. 운영비 반영

**상태:** `[확정]`

프로그램 처리:

- 선택 기간의 날짜별 비용 기록을 운영비로 합산한다.
- 월 비용 계획은 계획 비교용 자료이며 실제 손익에 다시 더하지 않는다.
- 재료 입고 금액은 재고 확보 기록이다. 판매 당시 원가와 중복되므로 실제 손익의 운영비로 다시 차감하지 않는다.
- 비용 기록은 월 비용을 날짜별로 나눈 값이므로 `실제 결제일 현금 지출`로 표현하지 않는다.

화면 결과:

- 운영비 합계와 포함된 비용 항목을 확인할 수 있다.
- 월 비용 계획은 `계획`으로 명확히 표시하고 실제 비용과 분리한다.
- `[결정]` 월·분기·반기·연간 조회에서는 해당 월의 계획 금액을 합산해 참고값으로 표시한다. 일·주간 조회에서는 월 계획을 임의로 나누지 않는다.

오류·예외:

- 같은 비용 ID가 두 번 있으면 중복을 알리고 한 번만 반영한다.
- 비용 금액이 비어 있거나 숫자가 아니면 해당 비용을 합계에서 제외하고 `비용 기록 확인 필요`로 표시한다.
- 월 비용 계획만 있고 날짜별 비용 기록이 없는 기간은 계획을 실제 비용으로 대신 사용하지 않는다.

### PNL-03. 판매 채널별 실적

**상태:** `[시안 반영]`

- 매장과 포장 채널별로 판매수량, 순매출, 직접원가, 공헌이익, 매출 비중을 구분한다.
- 포장 전용 재료 원가는 포장 판매에만 포함한다.
- 알 수 없는 판매 채널은 임의로 매장 또는 포장에 넣지 않고 `채널 확인 필요`로 분리한다.

계산 제안:

```text
채널 매출 비중 = 해당 채널 순매출 ÷ 전체 채널 순매출 × 100
채널 공헌이익 = 해당 채널 순매출 - 해당 채널 직접원가
```

전체 순매출이 0이면 매출 비중은 `계산 불가`로 표시한다.

## 5. 메뉴 수익성 기능

### MENU-01. 메뉴별 수익성 목록

**상태:** `[확정]`

사용자 동작:

- 사용자는 분석 기간을 확인하고 메뉴를 선택한다.

프로그램 처리:

- 선택 기간의 마감된 판매 기록을 메뉴별로 합산한다.
- 메뉴 수익성에는 식재료비, 포장비, 결제수수료만 포함한다.
- 임차료·인건비 등 운영비는 메뉴별로 나누지 않는다.

화면 결과:

- 메뉴명, 분류, 판매기준가, 채널별 판매수량, 총 판매수량, 순매출, 할인·수수료, 식재료비, 포장비, 직접원가, 공헌이익, 마진율을 표시한다.
- 메뉴 수익성이 매장 전체 손익과 다르다는 안내를 표시한다.
- 시안의 `최고 마진율 메뉴`, `최다 판매 메뉴`는 위 목록의 같은 기간 자료로 요약한다.
- 자료의 메뉴 분류는 `음료`, `디저트`다. 시안의 `커피`, `논커피` 분류는 원본에 없으므로 사용하지 않는다.

계산 제안:

```text
메뉴 직접원가 = 메뉴 식재료비 + 메뉴 포장비 + 메뉴 결제수수료
메뉴 공헌이익 = 메뉴 순매출 - 메뉴 직접원가
메뉴 마진율 = 메뉴 공헌이익 ÷ 메뉴 순매출 × 100
```

오류·예외:

- 판매가 없는 메뉴는 판매수량·순매출을 0으로 표시하되 마진율은 `해당 기간 판매 없음`으로 표시한다.
- 순매출이 0 이하인 메뉴의 마진율은 `계산 불가`로 표시한다.
- 원가가 하나라도 확인되지 않으면 공헌이익과 마진율을 계산하지 않고 빠진 항목을 표시한다.

### MENU-02. 메뉴 상세 원가

**상태:** `[시안 반영]`

사용자 동작:

- 사용자가 메뉴를 선택하면 해당 메뉴의 레시피 원가 상세를 확인한다.

프로그램 처리:

- 판매 기록에 저장된 레시피 버전과 판매 당시 원가를 기준으로 기간 합계를 표시한다.
- 새 판매 기록의 원가를 만들 때는 판매일에 유효한 재료 가격 이력과 해당 레시피 버전을 찾는다.
- 포장 채널 전용 레시피 항목은 포장 판매일 때만 적용한다.

새 판매 기록의 단위 원가 계산 제안:

```text
재료 기준단가 = 판매일에 유효한 구매가격 ÷ 구매용량
레시피 항목 원가 = 재료 기준단가 × 메뉴 1개당 사용량
개당식재료원가 = 포장 전용이 아닌 레시피 항목 원가의 합계
개당포장원가 = 해당 채널에 적용되는 포장 전용 항목 원가의 합계
```

- `[결정]` 유효한 가격은 판매일과 같거나 그보다 앞선 가격 이력 중 가장 최근 값을 사용한다.
- `[결정]` 재료별 계산 중간값은 반올림하지 않는다. 개당 식재료·포장 원가는 0.1원 단위로 저장하고, 판매수량을 반영한 합계 금액은 마지막 단계에서 1원 단위로 반올림한다. 화면의 금액은 1원 단위로 표시한다.

오류·예외:

- 판매일에 사용할 가격 이력이 없으면 새 판매 기록을 저장하지 않고 재료명과 누락된 가격 날짜를 알린다.
- 레시피 단위와 재료 기준단위가 다르면 자동 환산하지 않고 `단위 확인 필요`로 처리한다.
- 레시피 버전이나 메뉴 ID를 찾을 수 없으면 원가를 임의로 0원 처리하지 않는다.

### MENU-03. 메뉴 목록 필터·정렬과 제외 기능

**상태:** `[시안 반영]`, 제외 항목은 `[2차]`

- `[시안 반영]` 사용자는 전체·음료·디저트 분류로 목록을 좁힐 수 있다.
- `[시안 반영]` 사용자는 마진율 높은 순, 순매출 높은 순, 판매수량 높은 순으로 정렬할 수 있다. 마진율을 계산할 수 없는 메뉴는 마진율 정렬의 마지막에 둔다.
- 선택한 기간에 해당 결과가 없으면 빈 표 대신 `조건에 맞는 메뉴 실적 없음`을 표시한다.
- 시안의 메뉴 분석 다운로드는 PRD에 없는 파일 출력 기능이므로 1차 요구사항에 포함하지 않는다.
- `레시피 기준단가 수정`, `원재료 매입 변동 이력`, `원가 인상 시나리오`, `판매가 권장치`는 PRD의 2차 범위이므로 1차에서 동작시키지 않는다.

## 6. 재료·재고 기능

### INV-01. 재료별 예상 잔량

**상태:** `[확정]`

프로그램 처리:

- 재료별로 초기재고, 입고, 폐기, 판매에 따른 사용량, 실사 기록을 시간 순서로 연결한다.
- 실사 전에는 초기재고를 기준으로 잔량을 계산한다.
- 실사가 있으면 가장 최근 실측수량을 새 기준 잔량으로 삼고, 그 이후의 입고·폐기·판매 사용량만 반영한다.
- 실사 기록의 실측수량과 실사조정 증감량을 동시에 더하지 않는다.
- 포장 전용 재료는 포장 판매에서만 차감한다.

계산 제안:

```text
실사가 없는 경우
예상 잔량 = 초기재고 + 누적 입고 - 누적 폐기 - 누적 판매 사용량

실사가 있는 경우
예상 잔량 = 최근 실측수량 + 실사 이후 입고 - 실사 이후 폐기 - 실사 이후 판매 사용량

판매 사용량 = 판매수량 × 해당 레시피의 메뉴 1개당 재료 사용량
```

화면 결과:

- 재료 ID, 재료명, 단위, 공급사, 초기재고, 누적 입고, 판매 사용량, 폐기량, 최근 실측수량과 실사일, 현재 예상 잔량, 상태를 표시한다.
- 정상, 소진(0), 음수 상태를 구분한다.
- 음수 재고는 `기록 점검 필요`로 표시하고 해당 값을 숨기지 않는다.

오류·예외:

- 초기재고와 실사 기록이 모두 없으면 잔량을 0으로 표시하지 않고 `기준 재고 없음`으로 표시한다.
- 판매 기록에 연결할 레시피가 없으면 해당 판매로 인한 사용량을 추정하지 않고 영향을 받는 재료·판매를 알린다.
- 재료 단위가 일치하지 않으면 그 재료의 잔량을 `계산 불가`로 표시한다.
- `[결정]` 1차 실사는 해당 영업일의 판매·입고·폐기 입력을 마친 뒤 실시하는 마감 실사로 취급한다. 실측수량은 그 날짜의 모든 변동이 반영된 마지막 기준값이다.
- `[결정]` 실사를 저장한 날짜에는 같은 날짜의 판매·입고·폐기 기록을 나중에 추가·수정할 수 없다. 먼저 실사를 취소하거나 다시 등록하도록 안내한다.
- `[결정]` 미마감 날짜라도 저장된 판매는 실제 재고 사용으로 보고 예상 잔량에서 즉시 차감한다. 마감 여부는 손익 확정에만 적용한다.

### INV-02. 입고 기록

**상태:** `[확정]`

사용자 입력:

- 날짜, 재료, 입고수량, 단위, 공급사, 입고 단위원가, 사유

프로그램 처리와 결과:

- 필수값을 확인하고 입고 기록을 저장한다.
- 저장한 수량은 해당 재료 잔량에 증가 방향으로 반영한다.
- 판매 원가와 매장 손익에는 입고 금액을 중복 반영하지 않는다.

오류·예외:

- 입고수량이 0 이하이면 저장하지 않는다.
- 재료의 기준단위와 입력 단위가 다르면 자동 환산하지 않고 수정을 요청한다.
- 알 수 없는 공급사나 재료 ID는 저장하지 않는다.

### INV-03. 폐기 기록

**상태:** `[확정]`

사용자 입력:

- 날짜, 재료, 폐기수량, 단위, 사유

프로그램 처리와 결과:

- `[결정]` 사용자는 폐기한 양을 양수로 입력하고, 프로그램은 이를 감소 기록으로 저장한다.
- 저장한 수량은 해당 재료 잔량에서 차감한다.

오류·예외:

- 폐기수량이 비어 있거나 0 이하이면 저장하지 않는다.
- 폐기 반영 후 잔량이 음수가 되더라도 기록을 숨기지 않고 저장 전 경고한다. 저장하면 재고 화면에 `기록 점검 필요`로 표시한다.

### INV-04. 실사 등록과 잔량 보정

**상태:** `[확정]`, 입력 항목은 `[시안 반영]`

사용자 동작:

- 재료 목록에서 `실사 등록`을 선택한다.
- 실측수량, 조정 사유, 확인 메모를 입력하고 `새 기준 잔량으로 확정`한다.

프로그램 처리:

- 실측수량과 직전 예상 잔량의 차이를 실사 차이로 기록한다.
- 실측수량을 이후 잔량 계산의 새 기준으로 사용한다.
- 실사 차이를 잔량에 다시 더해 중복 보정하지 않는다.

화면·저장 결과:

- 최근 실측수량, 실사일, 실사 차이, 사유, 메모를 저장하고 표시한다.
- 실사 취소 시 어떤 값도 저장하지 않는다.

오류·예외:

- 실측수량이 비어 있거나 숫자가 아니거나 음수이면 확정하지 않는다.
- 같은 재료에 같은 시점의 실사가 둘 이상이면 자동으로 하나를 선택하지 않고 중복을 알린다.
- 시안의 `전체 실사 즉시 등록`은 PRD에 없는 일괄 기능이므로 1차에 포함하지 않는다.
- 시안의 `원장 수정`은 기존 입고·폐기·실사 기록의 편집으로 해석하며, 재료 기준정보 자체를 수정하지 않는다.

## 7. 기록 관리 기능

### REC-01. 기록 영역 전환과 목록

**상태:** `[확정]`, 탭 구성은 `[시안 반영]`

- 사용자는 판매 기록, 비용 기록, 재고 기록을 나누어 조회한다.
- 각 목록은 저장된 기록과 수정·삭제 동작을 제공한다.
- `[시안 반영]` 검색 입력칸은 현재 선택한 기록 종류 안에서 ID, 메뉴·비용항목·재료명, 판매채널·재고유형과 일치하는 기록을 찾는다. 검색어를 지우면 전체 목록으로 돌아간다.
- 한 화면에 모든 기록을 표시하지 않고 이전·다음으로 나누어 조회한다. 첫 페이지의 이전과 마지막 페이지의 다음은 사용할 수 없게 한다.
- 검색 결과가 없으면 `일치하는 기록 없음`을 표시하며 원본 기록은 변경하지 않는다.
- 시안의 기록 건수는 시각 예시이며 원본 데이터의 실제 건수를 사용한다.

### REC-02. 판매 기록 추가

**상태:** `[확정]`, 입력 구성은 `[결정]`

사용자 입력:

- 판매일, 메뉴, 판매채널(매장·포장), 판매수량, 판매당시단가, 할인금액
- 결제수수료 실제 금액

프로그램 처리:

- 판매 ID를 만들고 해당 메뉴의 레시피 버전을 연결한다.
- 순매출, 개당 식재료 원가, 개당 포장 원가를 계산해 판매 당시 값으로 함께 저장한다.
- 저장이 완료되면 메뉴 수익성, 실제 손익, 재료 잔량을 다시 계산한다.

오류·예외:

- 날짜·메뉴·채널·수량·단가 등 필수값이 없으면 저장하지 않는다.
- 판매수량은 0보다 커야 하며, 단가와 할인은 0 이상이어야 한다.
- 결제수수료는 필수이며 0 이상이어야 한다.
- 같은 일자·메뉴·채널의 기록이 이미 있으면 새로 더하지 않고 기존 기록을 편집하도록 안내한다.
- 미마감 날짜의 판매 기록은 저장할 수 있으며 재고에는 즉시 반영한다. 실제 실적에는 해당 날짜를 마감한 뒤 포함한다.
- `[결정]` 오늘보다 미래인 날짜에는 판매 기록을 입력할 수 없다. 미래 실적은 2차 예상 손익 기능에서 다룬다.

### REC-03. 비용 기록 추가

**상태:** `[확정]`, 입력 구성은 원본 자료 기준

사용자 입력:

- 귀속일, 비용항목, 금액, 배분기준

프로그램 처리와 결과:

- 비용 ID와 함께 저장하고 해당 날짜가 포함된 매장 전체 손익을 다시 계산한다.
- 메뉴 수익성에는 이 비용을 배분하지 않는다.

오류·예외:

- 날짜·비용항목·금액이 없으면 저장하지 않는다.
- 금액이 숫자가 아니면 저장하지 않는다.
- `[결정]` 1차 비용 금액은 0보다 커야 한다. 환급·취소를 나타내는 음수 비용은 지원하지 않는다.

### REC-04. 재고 기록 추가

**상태:** `[확정]`

- 사용자는 입고, 폐기, 실사조정 중 유형을 선택한다.
- 유형에 따라 INV-02~INV-04의 입력과 검사를 적용한다.
- 저장 후 재료 잔량과 상태를 다시 계산한다.

### REC-05. 기록 수정

**상태:** `[확정]`

- 사용자는 판매·비용·재고 목록에서 기록을 선택해 저장된 값을 수정한다.
- 수정 전 기록의 영향을 제거하고 수정 후 값을 한 번만 다시 반영한다.
- 판매의 날짜·메뉴·채널을 바꿨을 때 다른 기존 기록과 중복되면 저장하지 않는다.
- 수정에 실패하면 원래 기록과 기존 계산 결과를 유지한다.

### REC-06. 기록 삭제

**상태:** `[확정]`, 확인 절차는 `[결정]`

- 삭제 전에 대상 기록과 영향받는 결과가 바뀐다는 점을 알리고 확인을 받는다.
- 사용자가 확인하면 기록을 삭제하고 관련 결과를 다시 계산한다.
- 사용자가 취소하면 기록과 결과를 유지한다.
- 삭제 저장에 실패하면 기록을 유지하고 오류를 알린다.

### REC-07. 날짜 마감 관리

**상태:** `[확정]`, 시안 부재

- 사용자는 날짜를 선택해 기록 완료 상태를 마감 또는 미마감으로 바꿀 수 있어야 한다.
- 마감하면 해당 날짜가 실제 실적·손익에 포함된다.
- 미마감으로 되돌리면 해당 날짜는 실제 실적·손익에서 제외되지만 입력 기록은 삭제되지 않는다.
- `[결정]` 기록 관리 화면 상단에 날짜 선택과 `마감 완료`·`미마감으로 변경` 동작을 둔다. 변경 전에는 대상 날짜와 결과 반영 여부를 확인한다.

## 8. 판매 엑셀 양식과 가져오기

### XLS-01. 판매 엑셀 양식 내려받기

**상태:** `[확정]`

사용자 동작:

- 사용자는 `판매 엑셀 양식 다운로드`를 선택한다.

파일 결과:

- 프로그램이 지원하는 판매 기록 양식 한 종류를 `.xlsx` 파일로 내려받는다.
- `[결정]` 사용자가 작성할 열은 판매일, 메뉴 ID, 판매채널, 판매수량, 판매당시단가, 할인금액, 결제수수료 실제 금액으로 구성한다.
- 판매 ID, 순매출, 레시피 버전, 개당 식재료 원가, 개당 포장 원가는 프로그램이 만들거나 연결하므로 사용자가 직접 작성하지 않는다.

오류·예외:

- 양식 파일 생성에 실패하면 빈 파일을 내려받지 않고 다시 시도하도록 알린다.

### XLS-02. 엑셀 파일 선택과 사전 검사

**상태:** `[확정]`, 검사 결과 화면은 `[시안 반영]`

사용자 동작:

- 사용자는 `엑셀 가져오기`를 선택하고 파일을 고른다.

프로그램 처리:

- 지원 양식과 파일 형식을 확인한다.
- 각 행의 필수값, 날짜, 숫자 형식, 메뉴 ID, 판매채널을 검사한다.
- 할인금액과 결제수수료는 0 이상인지, 할인금액은 판매수량과 단가로 계산한 판매총액보다 크지 않은지 검사한다.
- 저장된 기록과 파일 안의 기록을 일자·메뉴·채널 기준으로 비교해 중복을 찾는다.
- 정상, 오류, 중복 행의 수와 각 행의 이유를 구분한다.
- 검사만으로는 기록을 저장하지 않는다.

화면 결과:

- 파일명, 전체 행 수, 정상 행 수, 오류 행 수, 중복 행 수를 표시한다.
- 오류·중복 행은 행 번호, 문제 값, 제외 이유를 표시한다.
- 사용자는 파일을 교체하거나 양식을 다시 받을 수 있다.

오류·예외:

- `.xlsx`가 아니거나 파일을 읽을 수 없으면 가져오기 단계로 진행하지 않는다.
- 필수 열이 없거나 열 이름이 다르면 파일 전체를 지원하지 않는 양식으로 처리한다.
- 빈 파일이면 `가져올 판매 기록 없음`을 표시한다.
- 메뉴 ID를 찾을 수 없거나 판매수량이 비어 있으면 오류 행으로 제외한다.
- 기존 기록 또는 같은 파일의 다른 행과 중복되면 중복 행으로 제외한다.

### XLS-03. 정상 행 가져오기

**상태:** `[시안 반영]`

사용자 동작:

- 사용자는 검사 결과를 확인하고 `정상 N건만 가져오기`를 선택한다.

프로그램 처리와 결과:

- 정상 행만 판매 기록으로 저장한다.
- 오류와 중복 행은 저장하지 않는다.
- 저장이 모두 성공하면 가져온 건수와 제외한 건수를 알리고 관련 실적·수익성·재고를 다시 계산한다.

오류·예외:

- 정상 행이 0건이면 가져오기 버튼을 사용할 수 없게 한다.
- `[결정]` 정상 행을 저장하는 도중 한 건이라도 실패하면 해당 파일의 행을 하나도 저장하지 않는다. 기존 자료를 유지하고 실패 행과 이유를 표시한 뒤 다시 가져오도록 한다.
- 가져오기를 취소하거나 창을 닫으면 검사 결과만 닫고 기록은 저장하지 않는다.

## 9. 백업과 복원

### BAK-01. 전체 백업 파일 생성

**상태:** `[확정]`

사용자 동작:

- 사용자는 `백업·복원`에서 `지금 백업 파일 생성`을 선택한다.

프로그램 처리와 파일 결과:

- 판매·비용·재고·영업 달력, 공급사·재료·메뉴·레시피·가격 이력·초기재고·월 비용 계획, 마감 상태, 제품 설정을 한 파일에 담는다.
- 백업 파일에는 자료의 버전과 생성 시점을 포함한다.
- 운영자가 파일을 직접 보관한다. 프로그램은 오래된 백업을 자동 삭제하지 않는다.
- `[결정]` 1차 백업은 JSON 파일 한 개로 생성하며 암호화하지 않는다. 파일명에는 매장 식별명과 생성 일시를 포함한다. 암호화 백업은 2차 보안 기능으로 둔다.

오류·예외:

- 필요한 자료 중 일부를 읽지 못하면 불완전한 백업을 성공으로 표시하지 않는다.
- 파일 생성에 실패하면 기존 자료는 변경하지 않고 실패 이유를 알린다.

### BAK-02. 전체 복원

**상태:** `[확정]`

사용자 동작:

- 사용자는 복원 파일을 선택한다.
- 프로그램이 파일을 검사한 뒤 현재 자료 전체가 바뀐다는 경고를 표시한다.
- 사용자가 확인하면 전체 복원을 진행한다.

프로그램 처리와 결과:

- 백업 구조, 필수 자료, 버전, 주요 기록 건수를 검사한다.
- 유효한 백업이면 현재 자료를 백업 내용으로 전체 교체한다. 기존 자료와 합치지 않는다.
- 복원 성공 후 주요 기록 건수와 기준일을 표시하고 모든 결과를 다시 계산한다.

오류·예외:

- 사용자가 취소하면 현재 자료를 유지한다.
- 파일이 손상됐거나 필수 자료가 없으면 복원을 시작하지 않는다.
- 지원하지 않는 버전이면 현재 자료를 유지하고 버전 오류를 알린다.
- 복원 도중 실패하면 현재 자료가 반쯤 바뀌지 않도록 복원 전 상태를 유지해야 한다.

## 10. 계산 결과의 공통 검증

| 검증 대상 | 정상 조건 | 문제가 있을 때 동작 |
|---|---|---|
| 판매 연결 | 메뉴·레시피 버전·채널이 확인됨 | 저장/가져오기 제외 또는 해당 결과 계산 불가 표시 |
| 가격 연결 | 판매일에 유효한 재료 가격이 있음 | 누락 재료와 날짜 표시, 원가 0원 처리 금지 |
| 재료 단위 | 레시피와 재료 기준단위가 일치함 | 자동 환산 금지, 재고·원가 계산 불가 표시 |
| 마감 범위 | 마감된 날짜만 실제 결과에 포함 | 미마감 날짜 수와 범위 표시 |
| 비용 중복 | 실제 비용과 월 계획을 따로 사용 | 같은 손익에 둘 다 더하지 않음 |
| 입고 금액 | 재고 기록으로만 사용 | 판매 원가와 운영비에 중복 차감 금지 |
| 실사 기준 | 실측수량을 새 기준으로 한 번 사용 | 실사 증감량 중복 반영 금지 |
| 비율 분모 | 순매출이 0보다 큼 | 마진율·이익률을 `계산 불가`로 표시 |

## 11. 시안과 PRD의 차이 처리

| 시안 요소 | 판단 | 1차 처리 |
|---|---|---|
| POS 동기화·연동률·자동 마감 | 외부 시스템 연동으로 PRD 제외 항목 | 표시·동작하지 않음 |
| 알림·설정 버튼 | 구체 기능이 PRD에 없음 | 동작 기능으로 추가하지 않음 |
| 주문 건수 | 원본 데이터에 없음 | 판매수량만 표시 |
| 커피·논커피 메뉴 분류 | 원본은 음료·디저트 분류 | 원본 분류 사용 |
| 레시피 기준단가 수정 | 기준정보 편집은 2차 | 1차 미제공 |
| 원가 시뮬레이션·판매가 추천 | PRD 2차 분석 범위 | 1차 미제공 |
| 전체 재고 실사 | PRD에 없는 일괄 기능 | 1차 미제공 |
| 블루투스 저울 | 외부 시스템 연동 | 1차 미제공 |
| 실사 승인 권한 | 여러 사용자·권한은 2차 | 1차 미제공 |
| 메뉴 분석 다운로드 | PRD에 없는 출력 기능 | 1차 미제공 |
| 백업 암호화 | PRD에서 미정이었던 요소 | 1차는 암호화하지 않은 JSON, 암호화는 2차 |
| 시안의 메뉴·재료명과 건수 | 원본 샘플과 다름 | 원본 JSON의 8개 메뉴·11개 재료와 실제 기록 사용 |

## 12. 2차 기능 목록

다음 기능은 프로그램 방향에는 포함되지만 1차 구현 요구사항은 아니다.

- 마감 실적과 월 비용 계획을 참고한 당월 말 예상 손익
- 납기·안전재고 영업일과 예상 사용량을 반영한 부족 재료·권장 발주량
- 비용·재고·기준정보용 엑셀 양식과 가져오기
- 재료 가격, 메뉴 가격, 레시피 버전 관리
- 계획·실제·예상 비교
- 운영비를 메뉴별로 나눈 추가 수익성
- 자동·다중 시점 백업, 여러 사용자·권한·변경 이력, 여러 매장, 외부 시스템 연동

시안의 원가 시뮬레이션, 판매가 추천, 블루투스 저울 등은 2차 기능을 설계할 때 다시 범위 확인이 필요하다.

## 13. 1차 완료 확인 시나리오

1. 사용자가 마감되지 않은 날짜에 판매를 입력하면 기록은 저장되고 재고에는 즉시 반영되지만 실제 손익에는 포함되지 않는다.
2. 날짜를 마감하면 같은 판매가 메뉴 수익성·실제 손익에 포함된다.
3. 판매수량과 레시피에 따라 관련 재료 잔량이 바뀐다. 포장 재료는 포장 판매에만 반영된다.
4. 판매를 수정하거나 삭제하면 이전 영향이 제거되고 새 결과가 한 번만 반영된다.
5. 비용을 입력하면 매장 전체 손익만 바뀌고 메뉴 수익성은 바뀌지 않는다.
6. 입고·폐기·실사를 입력하면 재료 잔량이 바뀌며, 실사는 당일 마지막 기록으로 실측수량을 새 기준에 사용한다. 같은 날짜의 변동을 나중에 바꾸려 하면 실사를 먼저 취소하도록 안내한다.
7. 같은 판매 엑셀을 다시 올리면 기존 판매와 같은 일자·메뉴·채널 행이 중복으로 제외된다.
8. 엑셀의 정상 행만 가져오고 오류·중복 행은 결과와 이유를 확인할 수 있다. 저장 단계에서 한 건이라도 실패하면 해당 파일의 정상 행도 모두 저장하지 않는다.
9. 미마감 날짜가 포함된 연간 조회는 실제 포함 기간과 미마감 구간을 표시한다.
10. 전체 JSON 백업 후 기록을 바꾸고 복원하면 백업 시점의 전체 기록과 결과로 돌아온다.

## 14. 추천안 적용 결정 기록

사용자의 요청에 따라 남아 있던 항목은 모두 추천안으로 확정했다.

| 항목 | 확정한 동작 | 추천 이유 |
|---|---|---|
| 결제수수료 | 판매 합계의 실제 수수료 금액을 직접 입력 | 원본 구조와 같고 자료에 없는 수수료율을 만들지 않음 |
| 마감일 무매출 | 마감된 날짜에 판매가 없으면 실제 0원으로 처리 | 미마감과 무매출을 명확히 구분 |
| 월 비용 계획 | 월 이상 조회에만 계획 참고값으로 표시 | 일·주 단위로 임의 배분하는 오류 방지 |
| 실사 당일 순서 | 당일 변동 입력 후 마감 실사, 이후 같은 날짜 기록 변경 제한 | 시간 정보가 없는 자료에서 이중 반영 방지 |
| 미마감 판매와 재고 | 저장 즉시 재고에서 차감 | 실제 사용된 재료를 현재 잔량에 빠르게 반영 |
| 미래 판매 | 입력 불가 | 실제 기록과 미래 예상을 혼동하지 않음 |
| 폐기수량 입력 | 양수로 입력하고 프로그램이 감소로 저장 | 운영자가 음수 부호를 직접 관리하는 실수 방지 |
| 음수 비용 | 1차 입력 불가 | 환급·취소라는 새 업무 유형을 임의로 추가하지 않음 |
| 삭제 | 영향 안내 후 확인해야 삭제 | 실적·재고가 함께 바뀌는 실수 방지 |
| 마감 관리 위치 | 기록 관리 화면 상단에서 날짜별 관리 | 기록 입력과 완료 처리를 한곳에서 수행 |
| 엑셀 저장 실패 | 한 건이라도 실패하면 해당 파일 전체 저장 취소 | 일부만 반영되어 기록이 어긋나는 상황 방지 |
| 원가 반올림 | 중간값 유지, 개당 원가 0.1원, 합계·화면 1원 단위 | 반복 계산의 오차를 줄이고 원 단위 화면 유지 |
| 백업 파일 | 버전·생성 일시를 포함한 암호화하지 않은 JSON 한 개 | 원본 JSON 구조를 활용해 4시간 안에 복원 검증 가능 |

위 결정으로 1차 기능 요구사항의 제품 정책은 모두 확정됐다. 화면 배치의 미세 조정과 구현 기술 선택은 이 문서의 기능 범위를 바꾸지 않는 후속 작업으로 본다.
