# 프렙 카페 운영 관리 프로그램 PRD

- 문서 상태: 제품 방향·1차 범위 확정 — 계산·화면・기술 설계는 후속 단계
- 작성일: 2026-10-12
- 대상: 매장 운영자 1명
- 1차 구현 목표: 기획·화면 설계·개발·검사·배포를 포함해 4시간 이내
- 결정 근거: 사용자의 “모두 추천으로 선택해서 진행” 요청에 따라 아래 추천안을 채택했다. 이는 제품 결정이며 원본 자료에서 확인한 사실과 구분한다.

## 1. 한눈에 보는 자료 현황

### 확인된 사실

자료는 프렙 카페의 가상 매장 기록이며, 엑셀과 JSON은 같은 내용을 담은 두 가지 형식이다. 한 형식만 한 번 가져와야 한다.

| 기록 | 건수 | 포함 내용 |
|---|---:|---|
| 공급사 | 3 | 공급사 ID와 이름 |
| 재료 | 11 | 단위, 구매용량, 최초가격, 납기·안전재고 영업일, 공급사 |
| 메뉴 | 8 | 메뉴명, 판매기준가, 분류, 레시피 버전 |
| 레시피 | 22 | 메뉴 1개당 재료 사용량, 포장 판매 전용 재료 여부 |
| 재료 가격 이력 | 33 | 가격 적용 시작일, 구매가격, 구매용량 |
| 영업 달력 | 457 | 영업·마감 여부, 날씨, 메모 |
| 판매 기록 | 6,112 | 일자·메뉴·판매 채널별 수량, 할인, 순매출, 수수료, 당시 원가 |
| 초기 재고 | 11 | 첫 영업일 시작 전 재료 수량 |
| 재고 기록 | 1,515 | 입고 1,302건, 폐기 189건, 실사조정 24건 |
| 월 비용 계획 | 120 | 월별 8개 비용 항목의 계획 금액 |
| 비용 기록 | 3,560 | 월 비용을 날짜별로 나누어 기록한 금액 |
| 자료 정보 | 10 | 매장명, 출처, 통화, 기준 기간 등 |

- 실제 기록 마감일은 2026-09-18이다. 영업 달력은 2026-09-30까지 있으며, 이후 12일은 미마감 상태다.
- 금액은 원 단위이며 부가세를 제외한다. 재료 단위는 g, ml, 개다.
- 판매는 주문 1건씩이 아니라 일자·메뉴·판매 채널 단위의 합계다. 판매 채널은 매장과 포장이다.
- 판매 ID, 재고 기록 ID, 비용 ID와 주요 묶음 기준에서 중복은 발견되지 않았다. 메뉴·재료·공급사 연결에도 끊어진 ID가 발견되지 않았다.
- 판매·비용·재고 기록은 모두 2026-09-18까지만 있다. 미마감 날짜에 판매 기록은 없다.

### 기획할 때 주의할 점

1. 미마감 날짜는 매출 0원이 아니라 아직 기록이 끝나지 않은 날이다.
2. 월 비용 계획과 날짜별 비용 기록은 같은 비용을 다른 단위로 표현한다. 둘을 더하면 비용이 이중 계산된다.
3. 판매 기록에 든 당시 원가와 수수료는 과거 시점의 값이다. 이를 보존하고, 수익성의 비용 범위는 제품 결정 기록에 따른다.
4. 포장 재료는 포장 판매에만 적용된다. 모든 판매에 적용하면 재고와 원가가 과다 계산된다.
5. 실사조정에는 증감량과 실제로 센 수량이 함께 있다. 제품 정책상 실측수량을 이후 잔량의 기준으로 삼되, 두 값을 중복 반영해서는 안 된다.
6. 빈칸은 0이 아니라 해당 없음 또는 미입력이다. 수치 0과 구분해야 한다.
7. 연간 조회에는 일부 기간만 포함될 수 있다. 이를 1년 전체 실적으로 오해하게 만들면 안 된다.
8. 미래 매출 자료는 없다. 예상 손익과 발주량은 확정 실적과 구분하고, 2차 설계에서 전망에 필요한 세부 기준을 정해야 한다.

## 2. 제품 목표

매장 운영자가 판매 기록을 입력한 뒤, 같은 흐름에서 메뉴별 수익성, 기간 실적, 비용을 반영한 실제 손익, 재료별 예상 잔량을 확인할 수 있게 한다.

1차 구현은 다음 질문에 답하는 데 집중한다.

- 어떤 메뉴가 상대적으로 수익성이 좋은가?
- 선택한 기간의 판매와 비용 실적은 어떠한가?
- 현재 기록을 기준으로 어떤 재료가 얼마나 남아 있는가?
- 잘못 입력한 판매·비용·재고 기록을 바로잡고 자료를 보관할 수 있는가?

## 3. 대상 사용자와 사용 상황

### 대상 사용자

- 한 개 카페를 직접 관리하는 운영자 1명
- 회계나 데이터 분석 전문 지식 없이 일상적인 매장 용어를 사용하는 사람

### 대표 사용 상황

- 영업 후 판매 합계를 입력하고 메뉴별 결과를 확인한다.
- 임차료, 인건비 등 비용 기록을 추가하거나 잘못된 값을 수정한다.
- 재료 입고, 폐기, 실제 재고 확인 결과를 기록한다.
- 일·주·월·분기·반기·연간 단위로 마감된 실적을 확인한다.
- 기록을 파일로 백업하고 이전 상태로 복원한다.

## 4. 핵심 사용자 흐름

1. 운영자가 판매 기록을 직접 입력하거나 판매용 엑셀 양식으로 가져온다.
2. 입력된 판매가 메뉴별 실적과 수익성 확인에 반영된다.
3. 선택한 기간의 판매와 비용을 함께 보며 실제 손익을 확인한다.
4. 판매에 사용된 재료와 입고·폐기·실사 기록을 함께 보며 재료별 예상 잔량을 확인한다.
5. 필요하면 원본 기록을 수정·삭제하고, 저장된 전체 자료를 백업한다.

예상 손익과 권장 발주량은 이 흐름의 확장 목표다. 4시간 안에 핵심 흐름을 완성하기 위해 2차 범위로 둔다. 재료가 이미 소진됐거나 기록상 음수인 경우는 1차에서 확인할 수 있다.

## 5. 1차 구현 범위 — 4시간 MVP

### 5.1 초기 자료 사용

- 초기 샘플은 제공된 JSON 한 형식으로 준비한다. 전체 엑셀 원본을 자유롭게 가져오는 기능은 1차에 포함하지 않는다.
- 같은 자료를 두 형식으로 중복 반영하지 않는다.
- 자료 기준일과 마감 여부를 사용자가 확인할 수 있다.
- 1차는 제공된 메뉴·재료·레시피·가격 이력을 사용하며, 기준정보 편집은 2차로 둔다.

### 5.2 기록 관리

- 판매 기록을 추가·조회·수정·삭제할 수 있다.
- 비용 기록을 추가·조회·수정·삭제할 수 있다.
- 재고 기록에서 입고·폐기·실사조정을 추가·조회·수정·삭제할 수 있다.
- 각 기록에서 날짜, 대상 ID, 수량·금액 등 결과에 필요한 필수 정보의 누락을 알린다.
- 빈칸과 0을 구분해 보존한다.
- 운영자가 날짜별 기록 완료 여부를 관리할 수 있다. 입력했지만 아직 마감하지 않은 기록이 완료 실적과 혼동되지 않아야 한다.

### 5.3 엑셀 가져오기

- 1차에서는 판매 기록용 엑셀 양식을 내려받을 수 있다.
- 작성한 판매 기록 엑셀을 가져올 수 있다.
- 가져오기 전에 읽을 수 없는 행, 필수값 누락, 알 수 없는 메뉴 ID, 중복 가능성을 알려준다.
- 기존 기록과 중복되는 판매는 자동으로 더하거나 덮어쓰지 않는다. 수정은 기록 편집 기능으로 처리한다.
- 지원 범위는 프로그램이 제공하는 판매용 양식 한 종류로 제한한다.
- 비용·재고·기준정보의 엑셀 가져오기는 2차 범위로 둔다.

### 5.4 메뉴 수익성 확인

- 선택한 기간의 메뉴별 판매수량, 순매출, 할인, 결제수수료, 기록 당시 식재료·포장 원가 정보를 함께 확인할 수 있다.
- 메뉴끼리 수익성을 비교할 수 있는 결과를 제공한다.
- 메뉴 수익성은 식재료비·포장비·결제수수료까지 반영한 결과로 본다. 임차료·인건비 등 매장 운영비는 메뉴별로 나누지 않는다.
- 메뉴 수익성은 매장 전체의 최종 손익과 의미가 다름을 알 수 있어야 한다.
- 과거 기록을 현재 가격으로 다시 계산한 값과 판매 당시 기록값을 섞지 않는다.

### 5.5 기간 실적과 실제 손익 확인

- 일·주·월·분기·반기·연간 중 원하는 기간 단위를 선택할 수 있다.
- 마감된 날짜의 판매 실적과 비용 기록을 기준으로 실제 실적을 확인할 수 있다.
- 매장 전체 손익에는 기록된 운영비도 포함한다. 입고한 재료의 구매액과 판매에 반영된 원가를 같은 비용으로 중복 반영하지 않는다.
- 비용 자료는 월 비용을 날짜별로 나눈 기록이므로, 실제 결제일의 현금 지출과 같다고 표현하지 않는다.
- 주는 월요일부터 일요일까지, 월·분기·반기·연간은 일반 달력 기준으로 본다.
- 월 비용 계획은 실제 비용과 별도로 표시하고 이중 합산하지 않는다.
- 전체 기간보다 짧은 자료를 연간 조회할 때는 일부 기간 자료임을 알린다.
- 미래 예상 손익은 2차 범위로 둔다.

### 5.6 재료 잔량 확인

- 재료 11종의 초기 재고, 판매에 따른 사용, 입고, 폐기, 실사조정 기록을 연결해 예상 잔량을 확인할 수 있다.
- 포장 전용 재료는 포장 판매에만 연결한다.
- 실제로 센 재고와 기록상 예상 재고의 차이를 구분해 확인할 수 있다.
- 실제로 센 재고는 해당 시점 이후 잔량의 새 기준으로 사용한다. 기존 실사 증감량과 이중 반영하지 않는다.
- 잔량이 0인 재료와 음수인 재료를 구분해 확인할 수 있다. 음수는 기록 점검이 필요한 상태로 알린다.
- 앞으로 부족해질 재료의 예측과 권장 발주량은 2차 범위로 둔다.

### 5.7 저장·백업·복원

- 입력·수정된 기록을 다음 사용 때 이어서 볼 수 있게 저장한다.
- 전체 기록을 한 번에 백업 파일로 내보낼 수 있다.
- 백업 파일을 선택해 전체 기록을 복원할 수 있다.
- 복원 전에 현재 자료가 바뀐다는 점을 알리고 사용자의 확인을 받는다.
- 1차는 한 운영자가 한 기기에서 사용하는 범위다. 기기 간 동기화는 포함하지 않는다.
- 백업에는 운영 기록, 기준정보, 마감 상태와 제품 설정이 포함된다. 복원은 전체 교체로 제한하고 자료끼리 합치는 기능은 제공하지 않는다.
- 백업 파일은 운영자가 직접 보관한다. 프로그램이 자동으로 보관 개수를 제한하거나 오래된 백업을 삭제하지 않는다.

## 6. 2차 구현 범위 — 확장 기능

- 마감된 과거 영업 실적과 월 비용 계획을 참고한 당월 말 예상 매출·비용·손익. 실제 기록과 전망을 구분하고 전망 기준 기간을 알 수 있게 한다.
- 납기일, 안전재고일, 예상 사용량, 현재 잔량을 반영한 부족 재료와 권장 발주량
- 비용·재고 기록 및 메뉴·재료·레시피 등 기준정보용 엑셀 양식과 가져오기
- 재료 가격 변경, 메뉴 가격 변경, 레시피 버전 변경 관리
- 계획 대비 실제 실적과 예상치 비교
- 필요할 경우 운영비를 메뉴별로 나눈 수익성 비교
- 자동 백업, 여러 백업 시점 관리, 선택한 시점으로 복원
- 여러 사용자, 권한, 변경 이력
- 여러 매장 통합 관리
- 추가 분석과 시각화

## 7. 1차 구현에서 제외하는 항목

- 예상 손익을 위한 전망 방식 확정 및 계산
- 자동 발주 또는 발주서 전송
- 권장 발주량 계산
- 세금·부가세·회계 신고 처리
- 주문 건수, 고객, 결제 건별 분석
- 여러 매장·여러 사용자 운영
- 외부 판매·결제·회계 시스템 연동
- 화면 디자인 세부안, 기술 선택, 계산식, 코드 설계

## 8. 데이터 사용 원칙

### 자료에서 확인한 의미

- 달력의 마감 여부는 기록 완료 여부를 뜻한다. 미마감 날짜는 판매 0으로 볼 수 없다.
- 월 비용 계획과 날짜별 비용 기록은 서로 다른 지출로 취급하지 않는다.
- 판매 기록의 당시 단가·원가·수수료는 과거 기록이다.
- 재료와 메뉴는 ID로 연결되며, 재료마다 g·ml·개 단위를 사용한다.
- JSON의 settings는 비어 있다. 원본에 제품 정책이 미리 합의돼 있는 것은 아니다.

### 이번에 채택한 제품 원칙

- 과거 판매 당시 값을 보존하고 현재 가격 변경으로 과거 실적이 바뀌지 않게 한다.
- 메뉴 수익성에는 직접비용만 포함하고, 운영비는 매장 전체 손익에 포함한다.
- 재료별 단위와 기록 연결을 유지하며, 없는 값을 0으로 채우지 않는다.
- 기록 수정·삭제는 관련 수익성·손익·재고 결과에도 반영돼야 한다.
- 엑셀 중복은 자동 반영하지 않고 전체 백업 복원은 교체로 한정한다.
- 나머지 채택 내용과 쉬운 예시, 대안, 추천 이유는 12절에 기록한다.

### 후속 설계에서 정할 사항

계산식, 원가 적용의 세부 규칙, 전망에 사용할 과거 기간, 수익성 등급 기준, 실사 당일 기록의 순서, 기간 경계 처리, 화면 구성, 저장·배포 기술, 엑셀 열 구성과 상세 오류 처리 절차는 이 PRD에서 확정하지 않는다. 1차 결과에 영향을 주는 내용은 개발 전에 설계 단계에서 명시하며, 자료에 없는 값을 사실처럼 만들지 않는다.

## 9. MVP 완료 조건

다음 조건을 모두 만족하면 1차 구현을 완료한 것으로 본다.

1. 새 판매 기록을 입력한 뒤 해당 메뉴의 기간 실적과 수익성 결과에서 반영 여부를 확인할 수 있다.
2. 같은 판매 기록이 실제 손익과 관련 재료의 예상 잔량에도 연결된다.
3. 판매·비용·재고 기록을 각각 수정·삭제할 수 있고 결과가 함께 갱신된다.
4. 일·주·월·분기·반기·연간 조회에서 선택한 기간과 마감 범위를 구분할 수 있다.
5. 판매용 엑셀 양식을 내려받고, 정상 자료를 가져오며, 잘못된 자료는 문제를 확인할 수 있다.
6. 미마감 미래 날짜를 매출 0원으로 집계하지 않는다.
7. 월 비용 계획과 날짜별 비용 기록을 이중 합산하지 않는다.
8. 전체 자료를 백업하고 복원한 뒤 주요 기록 건수가 유지된다.
9. 제공된 샘플 자료로 핵심 흐름을 검사하고, 배포된 프로그램에서 다시 확인할 수 있다.
10. 실사 후의 잔량에 실측수량과 실사 증감량이 중복 적용되지 않는다.
11. 잔량 0과 음수를 구분하고, 같은 판매 엑셀을 다시 가져와도 매출·재료 사용이 중복 반영되지 않는다.

## 10. 4시간 작업 한도

| 구간 | 최대 시간 | 결과 |
|---|---:|---|
| 자료 확인과 기획 확정 | 30분 | 데이터 연결과 MVP 범위 확인 |
| 최소 화면 흐름 설계 | 25분 | 핵심 흐름과 필요한 정보 확정 |
| 1차 구현 | 115분 | 기록·마감 관리, 판매 엑셀, 기간 조회, 수익성·손익·재고 연결, 저장·백업·복원 |
| 검사와 수정 | 50분 | 핵심 흐름, 날짜 경계, 빈칸·0, 중복·복원 확인 |
| 배포와 최종 확인 | 20분 | 실행 가능한 결과와 남은 제한 확인 |
| 합계 | 240분 | 4시간 |

이는 확정 납기 보장이 아닌 작업 예산이다. 단일 운영자·단일 기기, 제공된 기준정보, 판매 엑셀 양식 한 종류, 기본 결과 조회만으로 범위를 제한한다. 기존 자료를 활용해 구현하는 소규모 시험용 제품을 목표로 한다. 꾸미기·차트·추가 분석은 제외하고 검사와 배포 시간을 확보한다. 시간이 부족해 필수 기능을 완성하지 못하면 그 기능은 미완료로 보고하며 MVP 완료로 처리하지 않는다.

## 11. 위험과 대응 방향

| 위험 | 영향 | 대응 방향 |
|---|---|---|
| 메뉴 수익성과 매장 전체 손익의 혼동 | 메뉴가 좋아 보여도 매장이 적자일 수 있음 | 직접비용 기준과 운영비 포함 결과의 의미를 구분 |
| 미래 매출 가정이 없음 | 예상 손익을 신뢰하기 어려움 | 2차에서 전망 방식과 가정을 명시 |
| 실사 증감량과 실측수량의 중복 반영 | 현재 잔량이 잘못 나올 수 있음 | 실측수량을 새 기준으로 삼고 이중 반영 검사 |
| 엑셀 재가져오기 | 같은 판매가 중복될 수 있음 | 중복은 자동 반영하지 않고 수정은 기록 편집으로 처리 |
| 일부 기간 연간 집계 | 연간 전체 실적으로 오해 가능 | 자료 포함 기간을 함께 표시 |
| 4시간 제한 | 넓은 기능이 불완전해질 수 있음 | 1차는 단일 사용자·핵심 흐름만 완성 |

## 12. 제품 결정 기록

사용자가 추천 방향의 일괄 채택을 위임했다. 아래는 그 위임에 따라 채택한 제품 결정이다. 구체적인 계산식과 상세 동작은 포함하지 않는다.

| 결정 | 선택지와 채택 결과 | 쉬운 예시 | 추천 이유 |
|---|---|---|---|
| 메뉴 수익성 | **직접비용만 채택** / 운영비까지 배분 / 두 결과 모두 | 아메리카노의 원두·포장·결제수수료를 반영하고 임차료는 매장 손익에서 확인 | 메뉴끼리 비교하기 쉽고 운영비 배분에 필요한 추가 가정을 줄임 |
| 예상 손익 — 2차 | **최근 마감 영업 실적과 월 비용 계획을 참고한 당월 말 전망 채택** / 직접 예상액 입력 / 여러 전망 비교 | 9월 18일 마감 자료로 9월 말까지의 참고 전망을 봄 | 보유 자료로 시작할 수 있고 실제와 예상의 경계가 명확함. 참고할 과거 기간과 계산식은 후속 설계 |
| 실사 재고 | **실측수량을 이후 잔량의 새 기준으로 채택** / 증감량만 사용 | 기록상 우유가 남아 있어도 직접 센 수량이 이후 기준이 됨 | 현장의 실제 재고와 맞출 수 있음. 실사 증감량은 중복 적용하지 않음 |
| 부족 판단·발주 — 2차 | **재료별 납기와 안전재고 영업일을 고려한 준비량 채택** / 모든 재료를 같은 며칠치로 준비 / 운영자가 목표수량 지정 | 납기가 긴 원두와 짧은 우유를 서로 다른 준비 기간으로 봄 | 원본의 재료별 특성을 활용함. 예상 사용량·구매 묶음 처리의 계산식은 후속 설계 |
| 조회 기간 | **월요일 시작 주간, 일반 달력 기준 채택** / 매장 고유 기준 | 1분기는 1~3월, 상반기는 1~6월, 연간은 1~12월 | 운영자가 이해하기 쉽고 추가 설정을 줄임 |
| 엑셀 중복 | **중복 자동 반영 안 함 채택** / 덮어쓰기 / 추가 합산 | 같은 날 같은 메뉴·채널 기록을 다시 올려도 두 번 팔린 것으로 만들지 않음 | 실적과 재고의 중복을 예방하며 수정 경로가 단순함 |
| 백업 복원 | **전체 백업·전체 교체 복원 채택** / 일부만 복원 / 기존 자료와 합치기 | 어제 백업으로 복원하면 어제 저장한 전체 자료 상태가 됨 | 누락·중복과 구현 범위를 줄임. 복원 직전 현재 자료도 별도 백업하도록 안내 |
| 백업 보관 | **운영자가 파일을 직접 보관 채택** / 자동 보관·정리 | 날짜가 다른 백업 파일을 필요에 따라 보관 | 4시간 MVP에 적합하고 보관 개수나 자동 삭제 정책이 불필요함 |

1차 범위는 단일 운영자·단일 기기를 기준으로 채택한다. 복잡한 수익성 등급, 미래 부족 예측, 예상 손익, 발주 추천, 다중 기기 동기화는 2차에서 확장한다.
